2. 맛집 변경 내역 — 인계서 §6

추가 데이터 블록:
<!-- FOOD TREND DATA START --> ~ <!-- FOOD TREND DATA END -->
<script id="food-trend-data">window.FOOD_TREND_DATA = null;</script>

추가 UI 블록:
<!-- FOOD TREND START --> ~ <!-- FOOD TREND END -->
루트 #food-root. 모든 CSS 선택자는 #food-root로 범위를 제한했습니다.
화제도 카드, 조건 필터, 지역 칩/지역별 TOP 3, 모드 정렬, 담기, 좌표 포함 API, 산정 기준, 빈 상태.
이 블록에서는 외부 파일이나 API를 요청하지 않습니다.

기존 코드 수정 ① 관광 모드 이벤트:
전: 관광 모드 변경을 전달하는 TripTrend 인터페이스가 없었습니다.
후: 앞서 요청한 26개 도시 추천 모듈에서 모드 변경 후 triptrend:change를 발생시킵니다.
맛집 작업에서는 이 모드 이벤트를 구독하며 별도 모드 토글을 추가하지 않았습니다.

기존 코드 수정 ② TripContext:
전: food 필드 없음.
후: food: {kind:[...(state.opts.foodKind || [])], budget:[...(state.opts.foodBudget || [])], pref:[...(state.opts.foodPref || [])]}
배열을 복사해 외부 모듈이 기존 선택 상태를 직접 변경하지 않도록 했습니다.

기존 코드 수정 ③ 요약:
전: 맛집 행 = 음식 종류 + 예산 + 식사 조건.
후: 기존 문자열 + (window.FoodTrend ? window.FoodTrend.summaryText() : '').
추가: document.addEventListener('foodtrend:change', () => renderSummary()).

기존 맛집 버튼의 HTML/값/순서, 달력과 여행자 동작, budget.js는 변경하지 않았습니다.
stay.js는 로컬 편집하지 않았으며, 팀원의 최신 원격 변경을 pull로 반영했습니다.
상단 문구는 방문 통계로 오해하지 않도록 ‘검색 자료로 살펴본 요즘 맛집’으로 표현했습니다.
블로그 수는 ‘검색 결과 수’임을 명시했습니다. 실제 방문자 수/검색 횟수로 제시하지 않습니다.
